# MyMind

用思维导图管项目、把看到想到的收起来由 AI 整理、再配一个 AI 助手的桌面应用。用 Go 写成，界面是 [MyGo](https://github.com/egoist/mygo) 的原生 UI（GPU 绘制，没有 WebView），先做 macOS。

一个项目一张导图：模块、功能、细节、待办都是导图上的主题，主题可以是任务。收集来的东西留在「收集」，和导图之间用链接连起来。所有内容都是本机文件夹里的纯文本文件，可以同步到自己的 GitHub 仓库。

## 四个地方

窗口顶上一行在每一页都一样：左栏的开关、四个地方、一条输入栏、AI、搜索、设置。

| 地方 | 里面有什么 |
| --- | --- |
| **今天** | 今天要做的任务，列表、日、周、月几种看法；等着归位的；本周回顾；AI 动态 |
| **项目** | 所有导图，按文件夹；星标的在「快捷访问」。打开一张就是导图、大纲、看板、图解 |
| **收集** | 灵感、链接、图片、文档、视频，一面卡片墙；左栏按种类、标签、星标、未整理、含密钥筛选 |
| **技能** | 各个 AI 编程工具（Claude Code、Codex 等）的技能：在哪、有什么问题、收成一份、同步 |

左栏是把一页收窄的唯一办法：今天的各个列表和项目，项目的目录，收集的种类和标签。选中的任务、卡片或主题，详情在右边一栏。

## 一条输入栏

顶上那一条，写进去就展开成卡片（⌘J）。它记灵感、任务或链接，上面的标签说明这句话会记成什么，点一下可以改：

- 任务可以带日期、时间和重复：`明天 9点到10点半 开会`、`每周一 写周报`
- `#` 打标签，`[[` 链接到灵感、资料、导图或导图里的某个主题
- 边写边显示已经有的相近内容；以 `?` 开头是问 AI

在别的应用里也能记：全局快捷键弹出快速记录（默认 ⌃⌥Space），或把剪贴板直接存到收集（默认 ⌃⌥V）。菜单栏图标显示今天到期和逾期的任务。

## 导图

- 无限画布，一个文件多个画布；结构有思维导图、逻辑图、括号图、组织结构图、时间轴、鱼骨图
- 主题有备注（Markdown）、标签、标记、图片、附件、链接（网页、代码文件的某一行、别的主题、收集里的一条、一个技能）
- 自由主题、关联线、概要、外框；聚焦一个分支；多选；整枝复制粘贴，可以跨导图
- 同一份数据的几种看法：**导图**、**大纲**（当文字编辑）、**看板**（任务按状态分列）、时间线、总览
- 演说：把画布放成幻灯片；模板；历史版本（自动保留，可对比和恢复）
- 导入 XMind、Markdown、OPML，一个文件夹的 Markdown 文档可以导成一张导图；导出 XMind、Markdown、OPML、图片、PDF、日历（.ics）

### 图解

树说得清"什么在什么下面"，说不清"先后、变成什么、什么时候怎么决定"。在导图的「图解」页选一个主题，AI 把它的分支画成流程（分泳道）、状态、判定表和名词表，下面有三种读法：

- **讲一遍**：一步一句
- **拿例子走一遍**：AI 选一个例子，在每种图上走同一条路
- **考我**：盖住判定表的结果来答，答错的三天后回到「今天」

图解是导图的一种看法，不是另一种东西：每个方框都说得出它来自哪些主题，主题改了会提示；要改图就让 AI 重画。流程里回头路多的时候改用"步骤"来显示。可以存成图片，也能放进演说。

## 任务和日历

- 状态、优先级、日期；一天里的时间段；提醒时间（到点发通知，另外每天一次汇总到期和逾期的）
- 重复：按天、周、月（几号或第几个星期几）、年，法定工作日，到某天或若干次后结束
- **周和日按小时显示**：左边是钟点，全天的任务在上面一条，有时间的任务是一块；在空白处按下拖动就建一个任务，拖动任务改时间，拉下沿改结束时间，都可以撤回
- 日期旁边有农历和节气；中国的法定节假日和调休（休、班）每天从 [holiday-cn](https://github.com/NateScarlet/holiday-cn) 读取一次
- 本周回顾：做完的、逾期的、留下的，可以复制成周报，不用 AI

## 收集

- 记文字、粘贴链接（自动读标题和正文）、拖入图片、PDF、Word、PPT、Excel 和视频；重复的只定位到已有的那条
- **AI 整理**：起标题、写摘要、分类、打标签、生成同义词和分析，长短跟原文相称；图片和视频由 AI 看图（要用 Claude，DeepSeek 看不了图片）
- 搜索：中英文关键词；装上**语义检索插件**（约 23MB，离线，按需下载）后可以按意思搜，并推荐相关的；也可以换成外部的向量接口
- 回顾旧的灵感；一条资料可以标为"稍后归位"，在「今天」里等着放到某张导图上
- 灵感和任务各是各的，互相之间用链接变过去，不丢东西

### 加密

看起来像密钥或密码的内容，在卡片、标题和发给 AI 的文字里都是圆点。设了**加密密码**（设置 → 加密）之后，它们在文件里和同步出去时都是加密的，查看、复制或修改时才问密码，一段时间内只问一次；另有一个恢复码。规则认不出来的，可以把选中的一段标为密码，或把整条加密。都在「收集」的「含密钥」里找。

不加密的：文件和图片本身、链接的地址、导图里的主题，以及 GitHub 历史里以前已经上传的。

## AI 助手

浮在窗口右下角，哪一页都能叫出来。可以用 Anthropic Claude 或 DeepSeek，在设置里填 API Key、选择模型。它能看当前的导图、选中的主题和收集里检索到的资料；要改导图时先给出修改清单，点「应用」才写入，一步撤销。还有从文本或代码仓库生成导图、周报和日报、风险扫描等快捷操作。

## 同步和备份

- **同步到 GitHub**（设置 → 同步）：填一个私有仓库和只给它 Contents 读写权限的令牌。每 5 分钟一轮，这段时间的修改一起上传、别处的修改一起下载；也可以点「立即同步」
- 两台电脑改了同一张导图，按主题合并；同一处两边改得不一样时弹窗问用哪边
- 技能和导图一起同步
- **备份**（设置 → 备份）：打包成 zip，或每天自动备份到一个文件夹，保留最近 14 份

## AI 编程工具

帮助菜单「连接 AI 编程工具（MCP）」里有 Claude Code、Codex、Grok Build 的「复制命令」和「装上」。

- 一个项目一张导图：agent 在哪个代码仓库里工作，就用哪张（没有就新建）
- agent 能读简报（`project_brief`）、记待办和想法（`capture`）、记决策（`log_decision`）、收工记一笔（`log_session`），也能读写主题、列任务、检索和添加收集里的资料
- 「装上」会加两个 hook：会话开始时读简报，改了代码要收工时先记一笔
- 命令行运行 `MyMind mcp [--dir 导图文件夹]` 就是 MCP 服务（stdio）
- agent 记下的都在「今天」左栏的 **AI 动态**里，按天、按项目，逐条可以打开和撤回

## 截图

全局快捷键（macOS 默认 ⌃⌘A）定住屏幕，框选、调整、加框线、箭头、画笔和文字，然后复制、保存，或存到收集。支持多块屏幕和全屏应用。第一次用时系统会要「屏幕录制」权限。

## 安装

在 [Releases](https://github.com/wuyunyoujiduo-jpg/mindmap/releases/latest) 下载：

- **Apple 芯片的 Mac**：`mymind-x.y.z-arm64.dmg`，每个版本都有
- **Intel 的 Mac**（`-amd64.dmg`）和 **Windows**（`.exe` 安装包）：隔一阵才出一次，最新的版本没有时，用最近一个带它的版本

macOS 上打开 `.dmg`，把 MyMind 拖进「应用程序」。应用没有经过苹果公证，第一次打开前在终端执行：

```sh
xattr -cr /Applications/MyMind.app
```

不想手动放行，可以用仓库里的 `update.sh` 来装（命令行下载的文件不会被 macOS 隔离）。仓库是私有的，先装好并登录 GitHub 命令行工具：

```sh
brew install gh && gh auth login
gh api repos/wuyunyoujiduo-jpg/mindmap/contents/update.sh -H "Accept: application/vnd.github.raw" > ~/mymind-install.sh
bash ~/mymind-install.sh          # 装最新的版本；后面加版本号装指定的版本，-f 重装
```

### 更新

装好之后不用再下载：MyMind 每天检查一次，有新版本时显示更新说明，点「安装更新」后自动下载并重启。菜单 MyMind →「检查更新…」可以马上检查；开关在 设置 → 通用 →「自动检查更新」。

## 文件

第一次启动时在 `~/Documents/MyMind` 建一个文件夹，放一份「使用指南」；可以换成别的文件夹。里面：

- `名称.mindmap.json`：一张导图，缩进的 JSON，适合用 git 比较；图片和附件在旁边的 `名称.assets`
- `.library/`：收集，一条一个 JSON 文件；图解和加密用的密钥文件也在这里
- `.sync/`：同步的记录

因为是纯文本，别的程序改了导图文件，应用会自动载入；编辑中又被改动时会问保留哪一份。

## 从源码构建

需要 Go 1.27 或更高（版本低时 `go` 命令会自己下载工具链）。

```sh
go tool mygo dev      # 开发模式，改了代码自动重载
go tool mygo build    # 打包，结果在 build/
```

改动之后要过的检查（`CLAUDE.md` 的「Every change」）：

```sh
tools/check-mygo.sh                               # MyGo 有没有新版本
gofmt -l .
go vet ./...
go test ./...
GOOS=darwin GOARCH=arm64 go build -o /dev/null .
GOOS=windows go build -o /dev/null .
go tool mygo vet
MINDMAP_SNAPSHOTS=<目录> go test .                 # 把界面截图存下来看
```

界面测试用 MyGo 的 `ui.Tester` 在内存里渲染、点击和输入，不开窗口。系统层面的功能（全局快捷键、通知、截图、更新）要在真机上按 `docs/真机测试清单.md` 过一遍。

`CLAUDE.md` 是这个项目的设计备忘：每一处为什么是现在这样、代码在哪个文件。`DESIGN.md` 逐项说明界面的样式。`docs/审查清单.md` 是通读代码后留下的待定问题。

## 发布

在 `main` 上：改 `mygo.json` 的 `version`，在 `CHANGELOG.md` 加这一版的说明（更新窗口显示的就是它），推送，然后在 Actions 页面运行 **Build** 工作流并勾选「发布 Release」。

- 构建之前先检查（`.github/preflight.sh`）：必须是从 `main` 运行、`v<版本>` 这个标签还不存在、版本号比线上的更新清单新。不满足就不发布
- 默认只打 Apple 芯片的包；勾选「也打 Intel Mac 和 Windows 的包」才打另外两种
- 先在本仓库创建 Release，最后才把签名的更新文件发布到公开仓库 `mindmap-models` 的 `desktop-latest`，各处的 App 从那里读到新版本；发布后清掉那里已经没有清单用到的旧文件
- 更新文件的签名密钥和发布用的令牌是 GitHub 环境 `mymind` 的 secret；签名和公证用的 secret 见 `.github/workflows/build.yml` 里的说明
- `tools/check-release.sh` 在本机用假的 GitHub 把发布脚本试一遍
