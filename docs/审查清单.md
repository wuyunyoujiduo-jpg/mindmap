## 一、AI、技能、截图、发布

### 会出错的

1. **发布流程没有防呆**（`.github/workflows/build.yml`）— 已证实
   - 不检查是不是从 `main` 发、版本号是不是比线上的新、`v<版本>` 这个 tag 是不是已存在。CLAUDE.md 里记的"旧分支盖掉新版本"就是这样发生的。
   - 更新文件先发布（152–156 行），GitHub release 后创建（161–169 行）。后一步失败时，所有 App 已经收到了更新。
   - 测试任务只跑 `go vet` 和 `go test`，不跑 `gofmt`、`mygo vet`、macOS 和 Windows 的交叉编译。Windows 编译坏了要到 `all: true` 才发现。
   - 建议：构建前加一步检查；先建 release 再发清单；测试任务补上这四项。
2. **`desktop-latest` 的文件只增不减**（`.github/publish-updates.sh:23-28`）— 很可能
   - 每版加一个包和最多三个增量包，没有清理。0.30.1 以来约 190 个版本。GitHub 单个 release 有文件数上限，到了就发不出更新。
   - 先看现在有多少：`gh api repos/wuyunyoujiduo-jpg/mindmap-models/releases/tags/desktop-latest --jq '.assets|length'`
3. **AI 的流式回复总时长超过 5 分钟就被掐断**（`ai.go:185`、`deepseek.go:101`）— 很可能
   - 超时是整条回复的，不是"多久没收到字"。大的"从代码仓库生成架构"会以"网络错误"收场，而且走不到"回复太长被截断，继续"那条路。
   - 建议：流式不设总时限，改成约 90 秒没有新内容才断。
4. **Claude 模型列表落后一版**（`ai.go:36-41`，README 第 70 行）— 已证实
   - 列的"最强"是 `claude-fable-5-1`，现在是 `claude-fable-5-2`。`go.mod` 里 `anthropic-sdk-go` 是 v1.80.0，也有新版；`tools/check-mygo.sh` 只看 MyGo。
   - 没改的原因：换模型会动到你已保存的设置和费用，应由你定。
5. **钩子里的 git 调用**（`mcp.go`、`internal/gitbase/gitbase.go`）— 存疑。这次已给每次 git 调用加了 15 秒时限、不抢 `index.lock`（`GIT_OPTIONAL_LOCKS=0`），钩子出错也安静结束。没在真机上和 agent 自己的 `git commit` 同时跑过，请留意是否还有卡住。
6. **`skills.Rename` 会改正文里所有 `name:` 开头的行**（`internal/skills/store.go:503-515`）— 已证实，但现在走不到（只有项目技能的"被全局的盖住"会调用，而项目技能已停用）。

## 二、收集与加密

### 会出错的

19. **密钥规则误伤中文和代码**（`internal/library/secrets.go:64-65`）— 已证实
    - `密码是什么时候改的我忘了` → `密码是••••••••`；`Token: 这是一个很长的中文句子…`、`max_tokens: maxTokensDefault,`、`token = strings.Split(line`、`The secret: understanding…` 都被当成密钥。
    - 开了加密后这些会被加密进文件、从搜索里消失、不给 AI 看，条目还算进「含密钥」。
    - 建议：值必须是 8 位以上的 ASCII 可见字符（中文规则 6 位），去掉"是"作分隔，排除 `a.b` 和以 `(` 结尾的。没改的原因：规则放松多少会漏掉真密钥，要你拿自己的条目看。
    - 连带的一处：没开加密时，把一条含密码的灵感「转成任务」，任务标题里是明文密码（`convert.go:25`、`vault.go` 的 `sealedOut`），而卡片上是圆点。没有直接改成全部打码，是因为上面的误伤会把普通的话永久变成圆点写进任务标题；规则收紧后再一起改。
20. **带 EXIF 方向的照片横着显示**（`thumbs.go:63-76`）— 已证实。手机竖拍的 JPEG 在收集的卡片、详情和导图节点缩略图里都是倒的；MyGo 的 `ui.DecodeBitmap` 会转正，App 自己的后台解码路径不会。
21. **删除或加入大文件时整个读进内存，而且在界面线程上**（`internal/library/library.go:240-275,325-358`、`libview.go:278-281`）— 已证实。删一个 1 GB 的视频会卡住窗口并占 1 GB，直到下一条提示出现。建议：删除改成移进 `.library` 下的废纸篓，加入改成流式复制。
22. **图片缓存只增不减，读不到的记一辈子**（`thumbs.go:45,80,88-99`）— 已证实
    - 详情和大图里看过的每张图整张留在内存；翻 200 张截图各约 20 MB。
    - 1170×20000 的长截图"缩略图"是 640×10940，28 MB。
    - 同步还没下完的文件被记成"图片缺失"，重启前不会再试。
23. **取消整条加密失败时，明文留在内存里没存**（`vault.go:360-364`、`secrets.go:423-430`）— 很可能（需要一条被两把钥匙加密的条目）。建议像 `showSecrets` 那样先在副本上解。
24. **闭包里抓着的条目指针，库重新加载后就过期了**（`libview.go:613-614`、`library.go:339-357`）— 很可能，少见。设密码时 `askVault` 自己会触发同步；同步重载了库的话，加密写到的是旧对象。建议抓 ID，用的时候再找。
25. **`a.async` 没有 panic 兜底**（`main.go:529`）— 后台任务里一次 panic 就退出整个 App。这次修了已知会触发的一处（网页解析），兜底本身要不要加由你定：加了会把错误藏起来。

### 用户感觉得到的慢（都有测量）

26. **收集的墙每帧对全文做密钥正则**（`libview.go:480,517`、`library.go:89-100`）— 已证实，这次找到的最大开销
    - 120 条 1500 字的笔记：每帧 171 ms；120 条没整理的 2 万字链接：每帧 1.03 秒，69% 在 `Mask`。（合成数据，每条都含 "key"/"token"；真实数据会好些，比例不变。）
    - 同因：`secretCount`（`side.go:471`）每次库变化扫全部；`vault.go:638-643` 在"设置 → 加密"没设密码时每帧扫全部。
    - 建议：每条的标题、卡片文字、是否含密钥算一次，保存时作废；每条规则只在它自己的字面量出现时才跑。
27. **在条目详情里每打一个字，全部重算**（`libview.go:674-679`）— 已证实，800 条笔记时每个字后一帧 1.17 秒。每个字都存盘、让索引作废、重算含密钥数、重建所有导图的引用索引。建议：停顿后再存；空查询不建索引；只更新这一条。
28. **每张卡片每帧都查一次反向链接**（`libview.go:555`、`mapanalysis.go:55,320-326`）— 已证实，150 张导图、120 张卡片时每帧约 29 ms。
29. **第一次建语义索引时窗口一阵阵卡**（`libmore.go:72-110`、`embed.go:161,214-238`）— 很可能。每 16 条就把整个 `vectors.json` 重写一遍。
30. **外面改一个文件，整个库在界面线程上重读**（`clips.go:54-75`、`vault.go:101-141`）— 很可能。agent 加一条或同步下来一条，中等大小的库约卡一秒。
31. **输入 `[[` 时每帧重活**（`wikilinks.go:41-86`）— 很可能。每帧克隆并排序全部条目，还可能把没读过的导图全部加载一遍。
32. 小的每帧开销：`plugin.go:220-224` 每帧读并解析插件清单；`refs.go:291-317`；`libmore.go:573-586`；`libview.go:245-268`；`libview.go:150,235` 的 `wallShown` 从不复位。

## 三、导图、大纲、看板、图解

### 会出错的

42. **正在画布上打的标题，文件被外面改动时丢掉**（`app.go:818-846,895`）— 已证实。按 Tab 新建、0.8 秒后自动保存、还在打字，这时 agent 的钩子写了这张图：输入框关闭，打的字没了，主题留一个空标题。建议：正在编辑时推迟重载。
43. **概要会变得看不见但还在**（`annotate.go:619`、`internal/layout/layout.go:90,140`、`more.go:158`、`summary.go:48`）— 已证实

## 四、同步、备份、数据模型

### 会出错的

66. **打开的导图有未保存的修改时，同步拉下来新版本：不合并，「保留我的版本」会丢掉另一台电脑的工作**（`app.go:749-752,818-823`、`history.go:56-71,123-137`）— 已证实。提示条写的是"其他程序（比如 AI）"，只能整份二选一。建议这里也做三方合并（`model.Merge`），冲突交给 `askMerge`。
67. **整份恢复备份后，下一次同步又把坏的拉回来**（`ghsync.go:45`）— 已证实。同步状态 `.sync/github.json` 在文件夹里，恢复的文件等于状态里记的"上次同步时的样子"，于是被判为"只有仓库变了"。这次已让备份不再包含 `.sync`；但旧备份还带着，而且同样的问题在 iCloud 上更隐蔽：设置里（`libmore.go:479`）建议把导图文件夹放 iCloud，iCloud 会把一台电脑的状态文件带到另一台。建议把状态移到文件夹外（配置目录，按路径哈希）。
68. **一台电脑改名、另一台编辑，同一张图变两张**（`ghsync.go:523-528`、`mapname.go:49-65`）— 很可能。改名在同步里是"删 + 加"，"这边删了、那边改了：保留"会把旧名字连同对方的修改带回来。改中心主题的标题就会自动改文件名，所以不用刻意改名也会遇到。
69. **仓库里找不到共同祖先时，同步永久失败，解释还是错的**（`ghsync.go:747-751,222-255`）— 已证实。仓库删了重建或改写过历史后，每轮都报"令牌能访问…但 GitHub 按填写的名字找不到它"。建议：祖先 404 时按没有祖先合并。
70. **同步期间被编辑的文件没有像注释说的"留到下一轮"**（`ghsync.go:743-745,758,586-602`）— 已证实。结果是一份"GitHub 冲突"副本，再被无祖先合并：删掉的主题回来了，每处不同都问一遍"不知道原来是什么"。
71. **技能脚本丢可执行位**（`ghsync.go:825-834,1069`）— 已证实。`run.sh` 0755 到另一台是 0644。
72. **合并细节**（`internal/model/merge.go:238-264,401-423`）— 已证实
    - 图片、位置、基线、重复规则按字段逐个合并：两边都换了图会问三次（文件、宽、高），可以答成混搭。应整体当一个值。
    - 标记按词合并会得到 `[flag:red flag:blue]`，破坏"每组一个"。
    - 不进入概要的主题：一边把 B1 移到概要下、另一边改它的名，B1 在图里出现两次。
    - 同步里的合并不留合并前的版本（只有冲突副本那条路留）；没打开的图可能因"那边删了、这边没动"丢主题而无从找回。
    - 待回答的合并问题只在内存里（`mergeask.go:24-47`），重启或自动更新后问题没了，保留的是这边的值，也不说。
73. **一个写不下去的路径卡住整个同步**（`ghsync.go:541-556`）— 很可能。Windows 不接受的文件名（`:`、`?`、结尾的点、`CON`）或超长文件名，每轮都在拉的阶段失败，推不出去。
74. **下载固定 2 分钟超时**（`ghsync.go:911-921`）— 很可能。50 MB 的文件 base64 后约 67 MB，慢线路上永远下不完，报错只有"context deadline exceeded"。
75. **`codeStatusOf` 在一帧里跑四个 git 子进程**，面板开着时每 20 秒一次，没有超时（`codesync.go:55-73`）。
76. **导图里存着某一台电脑的绝对路径**（`File.Project`，`file.go:17-19`、`links.go:92-97`）— 很可能。同步到另一台就指向不存在的地方；在那边重新选了文件夹，又把这边的改掉。`Repo` 字段就是为此而设，但 `projectDir()` 没用它。

## 五、今天与窗口外壳

### 会出错的

90. **勾掉重复任务：提示里的日子是错的，没有撤销，次数会漂**（`taskspage.go:216-224`）— 已证实。10-11 到期、10-10 勾掉，任务到了 10-12（周一），提示说「下一次：周二」；用的是 `tell` 不是 `tellUndo`；撤销最后一次只恢复状态，`Times` 不减，之后显示「共 3 次，已做 4 次」。
91. **提醒会重复**（`reminders.go:34-54`、`app.go:227-229`）— 已证实
    - "每天一次"的汇总按任务记，所以今天每多一个到期任务就再弹一次；今天页的添加行给每条都盖今天的日期，于是每加一条就通知一次。
    - 写了一个今天已经过去的时间（9:30 时写「9:20 第三件」）立刻弹「到时间了」。
    - 已提醒的记录只在内存里，每次重启（包括自动更新）都重发。
92. **写下的一行被误读**（`taskspage.go:404-503,2219-2268`、`capture.go:67`、`today.go:85`）— 已证实
    - 重复词不要求边界：「工作日报 已提交」成了周一到周五的任务「报 已提交」；「每天都很累 想休息」成了每天的任务「都很累 想休息」，在收集页的输入条里也是。
    - 小数和范围被当成日期：「升级到 1.2 版本」到期 1 月 2 日、标题「升级到 版本」；「买 2-3 个苹果」是 2 月 3 日；「看 3.5 寸屏」是 3 月 5 日。这三句都会被判为任务。
    - 「明天9点开会」「9点开会」（不带空格）读不出时间；「晚上12点」成了中午 12:00；跨午夜的时段丢掉结束时间；「9点到9点」成了 9:00–21:00。
    - 「31号」在 11 月成了 12 月 1 日；「2月30日」成了 3 月 2 日。
    - 输入条里的清单（「- [ ] 买菜⏎- [ ] 做饭」）被记成一条任务。
    - 「每周 开例会」「每月 交房租」读不懂，而每天/每年/每2周可以。没给日期的地方加「每2周 …」会得到有重复、没日期的任务。
    - 没改的原因：这些规则你每天在用，放宽或收紧哪一条应由你定。
93. **周和月视图的添加行按一个过时的隐藏日期**（`taskspage.go:808-811`）— 已证实。App 开着过了一夜，没写日期的一行被记到昨天，一出生就过期。
94. **改成全天后提醒还留在原来的钟点**（`weektime.go:624-627`、`taskspage.go:1524-1527`），行上显示「今天 9:00」，提醒照样响。
95. **数字和它数的列表对不上**（已证实，在欢迎导图上）
    - 左栏项目行数的是 `countsAsTask`（3），页头数的是所有没做完的（「4 要做」），列表里还有一条没日期的想法。
    - 项目页的数字和卡片也按全部任务数。
    - 左栏「今天」把有日期的想法算进去，页头的「要做」不算，列表里显示。
    - 「做完」算了今天完成但没日期的任务，而列表跳过没日期的，于是「做完 1」下面没有「已完成」。
    - 重复任务勾掉后状态回到待做，所以从不计入做完、已完成和本周回顾。
    - 本周回顾的"拖着"和提醒汇总只看到期日，列表看的是到期日或开始日。
96. **迟到的重复任务的"影子"**（`repeat.go:306-320`）— 已证实。晚了一周的每日任务在过去每一天和今天都显示影子；晚了 400 次以上的一个都不显示，却每帧多算 400×7 次。
97. **⌘⇧L 绑了两次**（`main.go:570` 打开收集，`canvas.go:1495` 关联线）— 很可能。菜单优先，画布上的那个就失效了；速查表写的是连线。
